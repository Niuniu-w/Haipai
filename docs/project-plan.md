# AI 小说转剧本工具项目计划

## 1. 项目概述

### 1.1 项目目标

开发一款面向小说作者的 AI 辅助剧本创作工具。用户可以导入包含 3 个及以上章节的小说文本，系统自动识别章节、分析人物和剧情，并生成可编辑、可导出的 YAML 格式结构化剧本初稿。

### 1.2 核心价值

- 降低小说改编为剧本的门槛。
- 将长文本改编过程拆分为可查看、可重试、可编辑的步骤。
- 保留小说主要人物、关键事件和章节关系。
- 输出结构稳定的 YAML，方便作者继续修改或交给其他工具处理。

### 1.3 比赛演示目标

在 3 至 5 分钟内完整展示以下流程：

1. 导入一篇至少包含 3 个章节的小说。
2. 自动识别章节并展示分析结果。
3. AI 提取人物、故事概要和关键事件。
4. 分章节生成结构化剧本。
5. 在网页中编辑场景、动作和对白。
6. 实时预览并下载 YAML 文件。

## 2. 功能范围

## 2.1 MVP 必须实现

### A. 小说导入

- 支持直接粘贴小说文本。
- 支持上传 `.txt`、`.md` 和 `.docx` 文件。
- `.txt` 和 `.md` 自动兼容 UTF-8、GBK/GB18030 与常见 UTF-16 编码。
- 显示字数、章节数和文件名。
- 自动识别常见章节标题，例如：
  - `第一章 雨夜`
  - `第1章 雨夜`
  - `Chapter 1`
- 校验小说是否包含至少 3 个章节。
- 允许用户手动修改章节标题和章节划分结果。

### B. 小说分析

- 生成整部小说的故事概要。
- 提取人物列表及人物简介。
- 提取人物之间的关系。
- 提取每章关键事件。
- 识别题材、时代背景和整体风格。
- 分析结果可编辑，修改后用于后续剧本生成。

### C. AI 剧本生成

- 按章节逐一生成剧本，避免一次处理全文导致超出模型上下文。
- 每章可生成一个或多个场景。
- 每个场景至少包含：
  - 场景编号
  - 来源章节
  - 场景标题
  - 时间
  - 地点
  - 出场人物
  - 场景氛围
  - 动作描述
  - 人物对白
  - 来源剧情摘要
- 展示整体生成进度。
- 支持失败章节单独重试。
- 支持单章重新生成。

### D. 剧本编辑工作台

- 左侧显示章节与场景目录。
- 中间显示可视化场景编辑表单。
- 右侧显示实时 YAML 预览。
- 支持修改场景信息、动作和对白。
- 支持新增、删除和调整场景顺序。
- 支持新增、删除和调整对白顺序。
- 编辑后自动更新 YAML。

### E. 保存与导出

- 自动保存当前项目。
- 支持打开历史项目。
- 支持复制完整 YAML。
- 支持下载 `.yaml` 文件。
- 导出前执行结构校验。

## 2.2 比赛加分功能

- 提供改编模式：
  - 忠于原著
  - 影视化增强
  - 短剧快节奏
- 提供目标剧本类型：
  - 电影
  - 电视剧
  - 短剧
- 生成前允许设置目标场景数量和对白密度。
- 人物关系图可视化。
- 对剧本进行一致性检查：
  - 人物名称是否统一
  - 场景时间是否冲突
  - 是否遗漏关键事件
- 支持针对单个场景发出 AI 修改指令，例如：
  - “让冲突更强烈”
  - “减少旁白，增加对白”
  - “保持剧情不变，将场景改成夜晚”
- 显示每个剧本场景对应的原文来源。
- 提供内置示例小说，方便评委快速体验。

## 2.3 暂不纳入首版

- 多人实时协作。
- PDF、旧版 Word `.doc`、EPUB 等复杂格式解析。
- 完整影视行业标准剧本排版。
- 自训练模型或向量数据库。
- 复杂权限系统和付费系统。
- 手机端深度适配。

## 4. 系统架构

```text
浏览器
  |
  | HTTP / SSE
  v
Vue 3 前端
  |
  | REST API
  v
FastAPI 后端
  |-- 章节解析服务
  |-- 小说分析服务
  |-- 剧本生成服务
  |-- YAML 导出服务
  |-- 项目管理服务
  |
  |-- SQLite
  |
  `-- 大模型 API
```

### 4.1 AI 处理流程

```text
小说文本
  -> 章节规则识别
  -> 用户确认章节
  -> 逐章生成摘要和关键事件
  -> 汇总人物、关系和全局故事信息
  -> 结合全局信息逐章生成结构化场景 JSON
  -> Pydantic 校验
  -> 失败时自动要求模型修复
  -> 保存结构化剧本
  -> 转换为 YAML
```

### 4.2 为什么先生成 JSON 再导出 YAML

- 大模型生成 JSON 的结构约束能力更稳定。
- Pydantic 可以直接验证 JSON 对象。
- 验证通过后使用 PyYAML 转换，避免缩进错误。
- 前端可编辑结构化数据，并实时生成 YAML。

## 8. AI Prompt 与可靠性设计

### 8.1 Prompt 分层

- 系统提示词：定义专业剧本改编助手身份和输出规则。
- 分析提示词：只负责提取摘要、人物和关键事件。
- 生成提示词：只负责将单章转换为场景。
- 修复提示词：修复未通过 Pydantic 校验的输出。
- 润色提示词：根据用户指令修改单个场景。

### 8.2 上下文策略

生成每章剧本时提供：

- 全局故事概要。
- 全局人物表。
- 前一章摘要。
- 当前章节全文。
- 后一章摘要。
- 用户选择的改编模式。

这样能兼顾剧情连续性和调用成本。

### 8.3 容错策略

- 模型调用设置超时。
- 每章最多自动重试 2 次。
- 输出必须经过 Pydantic 校验。
- 校验失败时，把错误信息交给模型进行结构修复。
- 单章失败不阻塞其他章节。
- 保存每章生成状态，页面刷新后可以继续。

## 9. 开发阶段与里程碑

## 阶段 0：环境准备，预计半天

- 安装 Xcode Command Line Tools。
- 安装 Node.js 20 LTS 或更新版本。
- 安装 Python 3.11 或 3.12。
- 配置 VS Code 的 `code` 命令。

- 初始化 Git 仓库。

验收标准：

- `node --version`、`npm --version`、`python3 --version` 和 `git --version` 均可执行。
- 可以在 VS Code 中打开项目根目录。

## 阶段 1：项目骨架，预计半天

- 创建 `frontend` Vue 3 项目。
- 创建 `backend` FastAPI 项目。
- 配置前后端跨域。
- 添加健康检查接口。
- 创建首页和基础布局。

验收标准：

- 前端能访问后端健康检查接口。
- 前后端均能本地启动。

## 阶段 2：小说导入与章节识别，预计 1 天

- 完成文本粘贴和文件上传。

- 实现至少 3 章校验。
- 完成章节确认和编辑页面。

- 可以导入一篇示例小说，并正确识别至少 3 章。

## 阶段 3：AI 分析与剧本生成，预计 1 至 2 天

- 接入大模型 API。
- 实现章节摘要和人物分析。
- 定义 Pydantic 剧本 Schema。
- 实现逐章剧本生成。
- 实现生成进度和失败重试。

验收标准：

- 至少 3 个章节能够稳定生成结构化剧本。
- 输出经过 Pydantic 校验。
- 单章失败后可重试。

## 阶段 4：剧本工作台与 YAML 导出，预计 1 至 2 天

- 实现场景目录。
- 实现场景表单编辑。
- 实现 YAML 实时预览。
- 实现新增、删除和排序场景。

验收标准：

- 修改场景后 YAML 实时更新。
- 下载的 YAML 可以重新解析且字段完整。

## 阶段 5：加分功能与体验优化，预计 1 天

- 添加改编模式。
- 添加单场景 AI 润色。
- 添加一致性检查。
- 优化加载、错误和空状态。
- 添加内置示例小说。

验收标准：

- 无需用户准备文件即可完成完整演示。
- AI 失败时页面有明确提示，不会卡死。

## 阶段 6：测试、部署与演示准备，预计 1 天

- 测试完整主流程。
- 准备固定示例小说。
- 部署前端和后端。
- 配置线上环境变量。

验收标准：

## 11. 测试计划

### 后端重点测试

- 章节识别能处理中文和英文标题。
- 少于 3 章时返回正确错误。
- AI 输出缺少字段时能够发现并修复。
- YAML 导出后可以被 PyYAML 再次读取。
- 单章重试不会重复生成其他章节。

### 前端重点测试

- 上传错误文件类型时有提示。
- 生成过程中刷新页面后状态可以恢复。
- 修改场景后 YAML 立即同步。
- 删除场景前有确认提示。
- API 失败时有明确错误信息。

### 演示前检查

- 使用固定测试小说完整走一次流程。
- 准备已经生成完成的备用项目。
- 检查线上 API Key 和模型额度。
- 检查 YAML 下载文件能正常打开。

## 12. 风险与应对

| 风险 | 应对方案 |
| --- | --- |
| 小说太长导致超出模型上下文 | 分章分析和生成，只传递必要的全局摘要 |
| AI 输出结构不稳定 | 使用结构化 JSON、Pydantic 校验和修复重试 |
| 模型调用慢或失败 | 显示分章进度、支持重试、准备演示缓存 |
| 比赛现场网络不稳定 | 内置示例和预生成项目，准备备用视频 |
| 功能范围过大 | 优先完成 P0，避免过早开发人物关系图等功能 |
| YAML 被用户编辑坏 | 显示语法错误，保存和导出前再次校验 |
